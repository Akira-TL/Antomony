# 扣分数值与实际更新强度

## 用户关注与当前事实

用户指出陷阱不是即死，接触时应该有大量扣分。当前危险每次接触增加0.08伤害，达到1才死亡，约13次持续接触。`survival-v1` 每次接触反馈负0.08，死亡当步额外负1；没有探索或搬运正奖励抵消。单位是实现选定的数值，不是已验证最优权重。

负反馈立即记录，但候选通常凑满16步或死亡才产生。实际[时序分析](../../analysis/survival-timing/README.md)中26次危险死亡的5次在死亡当步才首次写入，21次此前已有受伤后写入。不能说根因只有延迟，也不能说先写入就一定来得及正确转向。

## 为什么单纯放大惩罚可能没有用

当前 `TrustDirectionLearner.propose` 先求梯度，再求分布度量下的方向，随后按该方向的二次型归一化到允许的分布变化。固定同一观察与行动、历史基线为0、把全部窗口反馈乘正数c时：梯度和未归一化方向乘c，二次型乘c平方，归一化再除c。理想算术下最终候选不因此放大。回溯仍要求实际行动分布变化在原有界限内。

`tests/training/test_trust_candidates.py::test_uniform_penalty_scaling_does_not_increase_normalized_trust_step` 用相同16步局部观察及随机行动，对比每步负0.08和负8。梯度放大100倍，但候选行动分布在数值容差内一致，参数步长没有放大超过1%。这检验当前代码行为，不是训练效果实验。

最初逐参数近乎相等的断言未通过，最大绝对差约0.000023，符合此测试低秩特征下求解的数值差异；因此最终检验实际行动分布及是否出现数量级步长放大，不伪称参数逐位相同。该边界不能推广到只改变一类奖励的相对权重、非零基线、不同状态轨迹或学习接受器输入的情况。

## 下一步边界

不能仅把扣分数字改大就声称更强地学会避险，也不直接移除更新范围保护。应分别验证负反馈到达后的响应时机与候选是否朝有利方向调整；先保留当前负结果。任何新触发方式、目标或课程均独立测试和冻结，不覆盖8774或旧检查点。

新增默认关闭的 `feedback_trigger="negative-feedback"`：仅在已发生反馈模式中，当步负反馈即可提前处理当前积累窗口；非负反馈继续最多积累16步。提前提出不强制接受，仍有接受/跳过流程，不向网络额外提供危险类别。当前只是固定触发机会的诊断开关，不宣称触发时机已经由模型学会。此前参数与记忆隔离、分布约束和残差上限不变，新触发配置禁止直接使用旧接受模型。
