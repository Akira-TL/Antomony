# 赛道二定位、现场演示与两天开发方案

## 当前判断

本文件根据用户本轮提供的半开放神经网络赛题，以及 MathHackson 提交 `b9b8751` 的实际代码状态形成。这里只规划，不代表训练、演示程序或模型收益已经实现；最终报名、既有代码使用和提交要求仍以主办方确认的信息为准。

当前 `FastResidualParameter` 是可逆参数执行模块，不是一套完整神经网络。已有 20 项工程测试说明限定操作语义有检查依据，但没有证明模型适应能力、自主回退策略或泛化收益。直接拿参数容器参赛，容易被理解为权重管理工具；接入一个真实神经预测任务并证明受限条件下的价值，才有足够完整的参赛内容。

建议定位为：**研究小型神经网络在线适应时，依据随后到达的反馈，选择性撤回有限的近期参数更新。** 核心问题是减少短暂错误反馈留下的后续损失，同时保留对持久规律变化的适应能力。网络拓扑本身不宣传为新发明，贡献候选是具体的更新组织、反馈时序、数学边界与实测效果。

## 最小参赛模型

第一版采用统一的浅层前馈神经网络：最近四次二维观测组成 8 维输入，经过 32 个双曲正切隐藏单元，再由一个含偏置的线性输出层预测下一次二维位置。隐藏特征在比较期间固定；初始化方式、公共预热过程及是否学习过隐藏层必须披露。第一实现优先使用固定随机隐藏层和相同的输出层预热，不临时加入端到端训练或循环隐藏状态。

该结构的数值系数为 `8×32+32+32×2+2=354`；其中仅最后 66 个参数在线适应。32 是待开发数据检查的工程起点，不是最优容量结论。所有学习方法使用同一个特征变换、输入顺序、预热初态和可适应参数集合。正式研究允许比较隐藏宽度，但不能用确认数据挑选。

现有参数容器管理这个输出层。第一阶段固定不进行在线巩固，先隔离“选择性回退是否有用”；巩固的输出保持性质可单独演示，不把存储位置变化当作已经证明的学习收益，也不添加第二个尚未验证的自学习控制器。

最近更新记录上限以 K=16 作为开发起点，有限反馈缓冲以 32 条作为开发起点。单次最多检查 16 个仍有效的增量、最多执行一次回退。同一次运行不能无限保存全部参数轨迹。仅增量数组的原始存储为 `66×16×4=4224` 字节，另加稳定/临时参数、特征缓冲、元数据和进程开销；4224 字节不是程序总内存。

具体候选公式、目标到达时序和研究判据以 [研究设计草案](../../designs/neural-readout-selective-rollback.md) 为唯一详细定义。自动解析求解不等于网络自主学会了决策规则。后续若另做可学习门控，必须独立设计与验证，本次不纳入关键路径。

## 现场演示

### 受众与核心时刻

受众是数学/机器学习评委。必须看到的不是“权重能减回来”，而是同样的观测流下，方法在短暂污染结束后的恢复表现与持久改变后的适应表现。两者必须并列，防止把拒绝学习包装成稳健。

演示内容是二维运动预测，不是机器人自主控制，也不是原始视频理解。程序生成真实轨迹，再经统一观测通道提供给各模型。模型只拿到历史观测，不拿到模拟器真状态、事件类型、倒计时、持续时间或未来位置。

### 建议三分钟演示脚本

| 时段 | 操作与画面 | 讲述内容与验收点 |
| --- | --- | --- |
| 0–20 秒 | 同场显示正常观测、提前预测位置和模型结构 | “我们只研究网络连续学习时，一个很小但关键的动作：近期学错的修改能否撤回。” |
| 20–50 秒 | 一次短暂坐标偏移/错误反馈，然后恢复正常 | 所有模型收到完全相同污染；展示实际预测和后续恢复，不预写“本方法必胜”的动画 |
| 50–85 秒 | 持久改变运动规律，例如转向系数或速度演化规律 | “不能把真正的新规律也当作错误删掉。” 同时展示冻结模型的适应局限 |
| 85–120 秒 | 在新规律已学习后叠加另一段短暂干扰 | 检查选择性回退能否保留新适应；与整体恢复对照，不能用特意很旧的劣质检查点制造优势 |
| 120–150 秒 | 评委选新的随机种子、扰动幅度或触发时刻 | 按钮只修改环境，不给算法传入事件标签，也不直接调用撤回；现场不保证每次都胜出 |
| 150–180 秒 | 打开固定新种子批量报告和一笔回退的证据记录 | 区分单次演示与总体证据；说明适用范围、失败条件、成本和赛前/比赛新增贡献 |

时段只是舞台编排建议，不是赛事规定。无法演示完整时，可缩成“短暂干扰—持久改变—总体结果”三段。

### 单页结构

中间是占主体面积的二维轨迹区域，至少区分真实位置、模型实际收到的观测和提前预测。为减少遮挡，可以使用同一坐标范围的并排模型视图。下方显示严格提前预测的误差曲线及累计误差；右侧显示真实网络的少量节点/权重、近期修改列表、回退比例和证据窗口。

首屏仅展示三种方法：普通在线学习、经开发数据选定的强对照、本方法。冻结模型、运动学模型及其余实验组放在对照切换或证据页。选择“强对照”的规则在确认实验前固定，不按现场结果切换到较弱对手。

回退解释区显示“第几笔可撤回增量、什么时候产生、之后收到了哪些证据、提出比例、确认结果、实际执行时间”。不能显示无法由代码或记录支撑的“神经元理解了环境”“正在产生意识”等状态。

建议模型步长 100 ms；页面插值可以以 60 帧/秒渲染，但必须分别标示模拟步长、模型更新频率和界面帧率。现场设备的完整计算路径第95百分位耗时低于 50 ms 是拟定性能目标，不是已经达到的结果。

### 失效后的真实降级

核心不依赖云端、账户、外部 API、摄像头或实时下载。启动脚本绑定本机回环地址，不改 nginx、路由或防火墙。提前在实际 Windows 浏览器/WSL 环境核验本地访问，不以修改网络配置解决临场问题。

若实时运行失败，播放提前保存的真实事件记录，页面醒目标记“已记录实验回放”；再退为本地报告和录屏。不把回放说成实时推理，不静默更换随机种子或隐藏不利曲线。原始教学材料不进入展示包。

## 两天开发切片

| 切片 | 工作与验收 | 依赖 |
| --- | --- | --- |
| 1：真实预测通路 | 数据生成器、8→32→2 网络、严格先预测后反馈、命令行运行与逐步记录；加入恒定位置/恒定速度及普通在线学习对照 | 已有参数模块；研究草案参数具体化 |
| 2：解析回退通路 | 有效增量身份、闭式比例、有限缓冲、后到证据确认、执行前重新校验、禁止未来数据；构造例子验证公式与实现一致 | 切片1 |
| 3：价值判断 | 相同预算的强对照、短暂污染/持久变化/无污染/组合场景；只在开发流上调整规则并报告失败 | 切片2；先登记对应探索工作 |
| 4：固定验证与可视化 | 配置、种子和分析规则冻结后进行确认；演示界面消费同一引擎事件，报告不从界面重算算法 | 切片3达到继续条件；运行前完成研究对象登记 |
| 5：现场可靠性 | 新种子交互、离线回放、日志定位、一键启动/停止、真实设备时延、三分钟演练 | 切片4 |

第一天重点完成1–3；第二天完成固定验证、界面和演练。不得为了赶工让“已看过的开发结果”变成确认结果。若截至第一天末仅有执行正确而无可重复改善，停止重型展示开发；可以交付有边界的机制研究，但不能宣称已经形成优越的学习算法。

界面构建可在事件契约稳定后与批量计算交错推进，不代表已经启动任何并行 Agent。一个负责数值与测试的开发者可以完成主线，界面工作可交由另一个开发者使用固定事件契约；没有队友时保持串行。

## 实现边界与文件计划

本轮不安装依赖、不创建下列尚未实现的模块。后续建议维持 NumPy 核心，提供 Python 本地服务与 TypeScript/React 单页；前端只显示与发送环境干预，不计算第二套模型。若使用 FastAPI，待进入实现时核实并锁定依赖；不需要数据库服务器或任务集群。

| 建议文件 | 唯一职责 |
| --- | --- |
| `src/mathhackson/streams.py` | 生成可重放轨迹；把模型观测与评估专用真值严格分开 |
| `src/mathhackson/predictor.py` | 固定特征变换、线性读出、预热与局部更新；不读场景标签 |
| `src/mathhackson/feedback.py` | 增量候选、证据资格、解析比例、后续确认与回退请求 |
| `src/mathhackson/events.py` | 明确类型的观测、提前预测、更新与回退事件 |
| `src/mathhackson/evaluation.py` | 相同流的比较、不可回写历史成绩、资源统计 |
| `src/mathhackson/api.py` | 本地会话和事件传输，不实现数学规则 |
| `web/` | 本地静态资源与展示，不调用云模型 |
| `configs/track2.toml` | 正式参数与数据划分；结果前冻结 |
| `scripts/run-experiment.sh` | 命令行实验入口，日志写 `logs/` |
| `scripts/start-demo.sh` / `scripts/stop-demo.sh` | 只启动、停止本项目自己的进程 |

关键公开接口建议是 `predict(observation_history)`、`observe(prediction_id, arrived_target)`、`propose_rollback(eligible_evidence)`、`apply_rollback(request)`。模型输入类型中不得存在 `is_corruption`、真实位置、下一状态、场景编号、事件剩余时间等字段。测试覆盖时间泄漏、相同输入公平性、记录过期、无效操作不改状态、数值不变量与确定性重放。

## 接受与淘汰条件

继续开发的理由必须是实际效果，不是神经网络术语数量。具体确认标准见研究设计；暂定产品目标是污染后预测损失至少相对改善10%，持久改变和无污染情境不恶化超过5%，且资源开销满足演示预算。这些数字是开发前提出的价值门槛，不是文献定律、官方指标或已经完成的结果；其可测性及最终值仍须在确认实验之前核验和固定。

若只在大异常尖峰上优于故意调坏的学习率、输给普通稳健损失、只有一个种子有效，或全部收益来自知道异常标签，则不接受强有效性主张。若模拟器规律过于简单，恒定速度预测始终更好，应承认该任务不足以证明神经网络必要性，而不是删除运动学对照。

## 参照资料与查新状态

检索日期为2026-09-25。以下是问题背景、最近邻方法与报告实践的有界核查，不是完整系统检索或新颖性确认。

1. Dohare 等，Nature 2024，Loss of plasticity in deep continual learning。https://www.nature.com/articles/s41586-024-07711-7 。说明持续适应问题重要，但本项目不复现实验，也不把短暂污染恢复等同于可塑性丧失。
2. Wang 等，CVPR 2022，Continual Test-Time Domain Adaptation。https://arxiv.org/abs/2203.13591 。包括随机恢复部分源模型权重；因此“模型可以恢复权重”不是新贡献。其无标签分类/分割设置不同，不直接比较本文成绩。
3. Chu 等，ICML 2025，Provable and Practical Online Learning Rate Adaptation with Hypergradient Descent。https://proceedings.mlr.press/v267/chu25a.html 。说明在线步长适应已有理论与实证，不能以自动学习率为原创口号。
4. Dorkenwald 等，Nature 2024，Neuronal wiring diagram of an adult brain。https://www.nature.com/articles/s41586-024-07558-y 。公开连接图谱是结构资源，不等于已经得到本项目可以直接复用的完整自学习算法；不推定赛题的“近期”必然指该项工作。
5. River 官方 progressive_val_score 文档。https://riverml.xyz/latest/api/evaluate/progressive-val-score/ 。作为目标按到达时间揭示、先预测后学习的实现参照，不强制安装 River。
6. NeurIPS Paper Checklist。https://neurips.cc/public/guides/PaperChecklist 。自愿采用其中声明范围、实验细节、误差条和计算成本报告实践，不把 NeurIPS 投稿规则当成本赛事要求。
