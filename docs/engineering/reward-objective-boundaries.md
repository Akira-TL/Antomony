# 奖励与短反馈窗口的工程边界

## 范围

2026-09-26，基于 `65ea71c` 实现新增确定性刻画测试。只检查现有公式和状态流；不训练、不更新旧参数、不替换8774，不替用户决定搬运与生存的取舍。人工构造行动与反馈不是已训练策略的实际表现，不构成新的自训练效果对照。

入口：`uv run --no-sync pytest -q tests/training/test_reward_objective_boundaries.py`。

## 原地探索仍有持续正反馈

使用当前 `bounded-local-v2` 场、有限巢穴信号和默认160步探索预算，单只在初始位置连续159步不动，无拾取、交付或返巢事件，每步探索分约0.003209，合计约0.5103；第160步预算归零才停止探索分。

原因有两个：探索分为 `0.005 / (1 + 浓度)`，对有限非负浓度始终为正；当前 `LocalTrailField.deposit` 用 `maximum` 合并新旧浓度，不是逐次相加。固定位置和释放强度下，测试中的浓度不会随等待次数增加。这推翻了“自身持续释放必然使原地探索奖励逐渐消失”的假设，但没有证明模型实际学会了利用这一点。

首次测试曾预期末步得分小于首步，实际两者完全相同，因此失败；检查沉积代码后将测试改为刻画实际恒定正反馈，而非把原预期作为通过证据。

## 空载短往返可反复获得返巢分

测试使用合法前进、转向和等待行动，不瞬移、不重置世界或预算。单只从离巢中心0.5的位置走到1.04，等待探索预算即将耗尽，再返回0.5。连续三趟483步，无拾取、无交付、无耗尽，却得到6分返巢奖励，另有正探索分。

这不是死亡复活误发奖励，也不是原地停在巢里重复领取返巢奖励；是当前“离开过、探索预算为零、实际到巢”条件允许的真实重复补给。三趟所需时间不能忽略，不能只比较6分与一次拾取交付5分就推导它是最优策略。

## 窗口边界影响惩罚归属

测试使用实际 `TrustDirectionLearner`、16步窗口、折扣0.995、`observed-window` 反馈和关闭的历史基线。人工输入每步0.005，并分别把-2.08惩罚放在第16或17步：

- 第16步受罚：第一窗口所有动作的回报均为负。
- 第17步受罚：第一窗口所有动作的回报均为正；提案处理后其动作概率与奖励记录已清空。第17步收到终止反馈时，只对新窗口的一个动作计算-2.08。
- 把17步作为整段手算，最早动作的回报为负，与实际首窗口正回报不同。

这不是奖励符号反转，而是窗口截断且后续价值为零的结果。测试不让模型偷看未来，也不主张将未来真实奖励用于之前已经执行的更新；下一方案需要合法保留过去动作的学习信息，或使用经过验证的后续价值估计。简单把窗口扩大不一定有效，已有16/64步对照不能被本测试推翻。

## 下一步边界

修订奖励时，必须一起检查固定释放方式、探索奖励和返巢事件，不能只改一个系数后假定其他约束仍有效。奖励总目标与反馈时间范围是两个问题，应分开验证。

本轮仅新增测试和说明。待确定搬运与死亡取舍后，先固定新的任务目标及辅助奖励范围，再冻结有限对照。当前测试描述旧行为，未来有意修改规则时应相应替换预期，不能将这些正反馈漏洞当作兼容性要求永久保留。
