# 记忆模型的更新流程接入

## 当前范围

接续[保持基础功能的初始化](preserved-memory.md)，新记忆模型现在可以执行推理、接收实际反馈、提出方向修正、接受或跳过、继续推理。工程上接通现有接受决策控制器和训练期配对分支，不等于接受网络已经训练有效，也不替换旧服务默认模型。

## 反馈来源

`AdaptationConfig.feedback_mode` 明确区分两种行为：

- `critic` 保留旧模型的价值估计与窗口末端估计，旧配置缺省仍采用此模式，不改变历史实验含义。
- `observed-window` 只用已经发生的窗口奖励。每个时点的更新系数为该时点至窗口末端的折扣奖励和，不减价值估计，末端之后的项取零。

新记忆模型的价值输出没有经过奖励校准，因此默认拒绝 `critic`，要求显式选择 `observed-window`。后者不访问下一个观察来估计未来收益；实际全部零奖励产生零候选，不会被随机价值输出驱动修改。窗口、折扣、概率变化约束和残差上限保持原定义。

这不是完整回合回报，也不是无偏的长期收益估计。它忽略窗口之后的后果，仍可能产生高方差或方向错误的候选，不能据此宣称信用分配问题已解决。只有真实后续对照能判断有无改善。

## 更新与隔离

本阶段只允许45个陌生信号方向修正参数参与在线候选。复制来的基础网络、64个记忆连接及82个动作参数都冻结，初始记忆连接仍为零。接受或拒绝由控制器处理当前提案，不能跳过实际行动反馈；每蚁参数、记忆和随机流独立。

训练期分支复制模型、历史与随机流，单独模拟接受和跳过的后果，不改父轨迹；这些未来结果只能作为离线标签，不进入部署输入。当前未重新训练接受网络，不沿用旧失败模型声称新结构有效。

## 保存与运行身份

方向修正快照的 `.residual.npz` 新增 `config_json`，同时保存反馈方式、窗口和约束配置。加载恢复该配置；显式传入不同配置会拒绝，不把恢复解释为更改实验。旧快照缺少此字段时仍按旧加载规则处理。

模型加载根据文件版本区分原循环模型与 `local-mlp-memory-v1`。快照保存参数与更新次数，不保存未完成计算图、世界状态或随机流，不能声称中途完整恢复仿真。

候选采样器新增显式 `policy_kind`、`policy_episode`。旧协议保持 `recurrent` 与第8回合；新的初始化模型需要 `mlp-memory` 与第0回合，同时显式选择已发生窗口反馈。它没有自动切换旧研究来源。

## 验证及下一步

`tests/training/test_memory_adaptation.py` 覆盖手算折扣回报、未校准价值拒绝、价值输出改变不影响候选、零奖励不产生候选、接受/拒绝、冻结和个体隔离、父分支保护、实际接受控制器、配置保存、新旧加载兼容，以及8步真实仿真的检查点读取、配对采样与末端参数保存。人工设置接受输出的测试仅核对控制流程，不作为学会接受时机的证据。

相关旧信号适配、方向候选、分支评价、接受模型、反馈采样及课程测试继续通过。

下一步应为这个明确的新来源和反馈方式固定一个有限预算课程，检查候选是否产生可学习的实际正负后果，再训练独立接受模型。新旧架构、价值处理和环境变化必须全部披露，不将跨版本差异归因于单一机制。完整普通MLP、规则和自学习模型在减速、周期、危险组合中的对照仍未完成。
