# 四帧更新判断

用户要求后续每四帧判断一次是否修改参数。新入口为：

```bash
bash scripts/training/four-frame.sh --smoke
```

去掉 `--smoke` 使用开发配置中的8只、2048步、两个世界种子。正式效果比较仍需另行冻结配对设计；最小运行检查不作为研究效果证据。每次输出独立写入 `logs/four-frame/`，不覆盖8774的既有轨迹。

## 判断与写入

新配置显式设置 `window=4`、`feedback_trigger="window"`。这里一帧是一次仿真行动与反馈，不是屏幕刷新。负反馈立即记录，但仅在累计第4、8、12步处理窗口；死亡或世界结束处理不足4步的剩余反馈。复活保留个体参数及隐藏状态，新生命重新积累窗口。

提出候选不等于修改。当前开发配置比较全部跳过、固定接受、普通MLP及纯规则；旧接受判断网络没有按新反馈与窗口训练，因此不放入新配置。固定接受仍须满足既有候选有效性和分布变化约束；不能把它称作已经学会控制更新。

每四步处理窗口不会把隐藏记忆也改成每四步推进。现有近期记忆为第1、2、3、4步，稀疏记忆为第4、8、12、16步，按行动步推进，本次保持不变。参数、随机流、记忆和反馈仍每只独立。

## 历史与记录

旧默认16步、已冻结协议及已有检查点不改写。新配置位于 `.research/protocols/four-frame-development.json`；每次执行保存展开配置、源文件校验值、全部判断与实际轨迹，每128步保存参数和记忆快照。尚不提供完整世界状态恢复。

单元测试验证负反馈不提前、连续窗口不重复用反馈、跳过不写入、短窗终止、复活重新计数及检查点保留四帧配置。实际运行记录另在本任务条目中引用。
