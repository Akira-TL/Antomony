# 生存优先的部署反馈接口

## 目标与边界

用户明确“生存优先于搬运”。原始环境奖励、既有参数文件和8774旧批次不改写，新配置显式选择 `feedback_profile="survival-v1"`，默认仍为 `legacy`。

本次实现只是可测试的部署接口，不是新的训练结果，也不构成模型已学会避险的证据。效果试验须另外固定设计、种子、判据和成本上限。

## 实际反馈

每个仍在行动的个体获得 `-本步失败 - min(本步新增伤害 / 伤害致死阈值, 1)`。范围为负2至0；失败指本步危险死亡或体力耗尽，一次失败只扣一次。不使用隐藏危险坐标、未来反馈或其他个体的结果。

探索、空载返巢、拾取、交付和复活都不产生正学习反馈；这些事件及原始环境奖励照常保存。待复活个体的反馈为0，不重复惩罚。新增伤害在释放复活队列之后、动作执行之前取起点，因此身体伤害清零不会产生正反馈。

这是工程候选反馈：伤害提供较早的局部负反馈，失败提供终止反馈，并不数学保证最终生存排序。现有16步窗口仍可能截断较早动作的责任；本次不同时改窗口、历史基线、参数量或学习率。搬运作为后续评价的次要指标，本轮先不加入它的正反馈。

## 与现有模型的关系

`ContinuousPlan.arms` 可显式限制比较组。新反馈禁止 `learned`，因为现有接受模型的训练目标仍是旧奖励；先用 `always` 与 `skip` 验证候选是否可能有用，允许加入普通多层感知机（Multilayer Perceptron, MLP）及纯规则对照。固定接受和全部跳过仍加载旧接受文件以保持既有检查点结构，但不会调用它做接受判断。

逐帧 `reward` 保留环境旧奖励；新配置的 `learning_reward` 才是传入更新窗口的值，`injury_delta` 为实际新增伤害。旧配置两新增字段为 `None`，历史轨迹缺失字段也按 `None` 读取，避免重建比较误报。

## 计数说明

`WorldResult.exhausted` 是历史命名，实际是所有终止次数，已包含 `deaths`。不得相加；体力耗尽为 `exhausted - deaths`。复活初始等待不算失败，危险与耗尽同一步时现有环境先处理耗尽，不重复记危险死亡。

新目标的效果评价应报告失败次数、其中危险死亡与体力耗尽、实际行动步数、伤害、交付以及参数写入。需要固定观察时限并处理提前交付完成的截断；不能仅用存活比例或旧总分掩盖反复复活、躲在巢内或减少行动。具体采用条件在正式试验设计中固定。
